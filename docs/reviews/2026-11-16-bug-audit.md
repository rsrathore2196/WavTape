# App bug audit — 16 November 2026

Reviewed from `82151453e9d20d45630d83dcbcdc49a91d59b124` on `main`.
The scope was correctness, recovery and redundant processing, preserving existing
features, layouts, glass rendering, styling and animation behavior.

## Changes in implementation order

1. **Last.fm now-playing recovery.** A request was marked delivered before its
   network operation succeeded. One transient failure suppressed further updates
   until another song or pause. Reconnecting during the same play also retained
   the previous session's delivered state. Network completion now returns to the
   existing serial snapshot consumer. Only a successful current-generation result
   marks delivery; failures can retry at a later measured checkpoint after a
   30-second cooldown. Session changes, pauses, disabled updates and new plays
   invalidate obsolete results and cancel their jobs. Listening measurements and
   durable scrobble qualification continue independently of these requests.

2. **Scrobble outbox recovery.** Reading and startup resumption checked only the
   atomic file's base path. A recoverable `.bak` file could consequently be
   ignored and replaced with an empty ledger. Reads now let `AtomicFile` recover
   the backup first. A genuinely missing ledger is empty; an unreadable existing
   ledger still raises its error. Startup resumption uses the recovered contents.

3. **Recording identity from original metadata.** Matching and identity keys used
   the potentially shortened display title even when the full provider title was
   retained. This could equate an original song with its slowed/reverbed version.
   Identity, version markers, featured credits and transliteration now use
   `fullTitle`. Temporary transliterated matching copies clear the untranslated
   title override so comparisons use the converted text. Playback matching
   thresholds and source priorities are unchanged. Artwork-only comparison
   copies likewise isolate normalized titles from raw upload captions, retaining
   the existing official-video/cast-tail matching and recording-version guards.

4. **Offline download metadata.** Download index serialization omitted songwriter
   credits and motion-artwork URLs. Both now round-trip across restart. The added
   JSON fields are optional when reading existing indexes. Audio storage,
   download representations and download quality policies are unchanged.

5. **Imported-lyrics fallback preferences.** Disabling an import wrote both its
   recording and title/artist fallback preferences, but reading checked only the
   recording preference. An alias from another provider could activate the
   disabled fallback. Reading now honors the fallback when no recording-specific
   preference exists, preserving an explicit recording preference's priority.

6. **Imported-lyrics atomic storage.** Imported lyrics used atomic writes but
   ordinary reads and base-file-only existence/deletion checks. Recovery now
   recognizes atomic backups and reads through `AtomicFile`; deletion removes
   its backup and uncommitted sidecars. Storage reads, writes and deletion share
   a lock so recovery cannot delete an active writer's temporary file. Only
   bounded file I/O holds the lock; decoding and parsing run afterward on the
   existing background dispatcher. UTF-8/UTF-16 support and the 2 MB import limit
   remain intact.

7. **Cached recommendation isolation and Home serialization.** A malformed track
   row previously discarded every other track in the same decoded result. Only
   malformed rows are now skipped. Home previously serialized existing JSON
   arrays to strings and reparsed them, in both directions. Shared array-based
   codec entry points remove those extra passes without changing the on-disk
   format, track limits or YouTube URL exclusion policy.

8. **Lossless position-preserving preparation.** The audio loader writes private
   transport/representation cache keys, but unindexed FLAC preparation checked
   completeness using the raw URL. Even a completed bounded cache fill was
   rejected, preventing a safe mid-song lossless activation. Preparation now
   resolves the same key as the loader. Complete span coverage, verified length
   and intact span files remain required; partial or truncated files are rejected.

9. **Catalog recording deduplication.** Catalog deduplication ignored retained
   provider titles and treated a shared ISRC as sufficient even for conflicting
   recording versions. A regression reproduced originals, slowed/reverbed songs
   and club mixes collapsing to the original. Deduplication now retains full
   titles and qualifies normalized ISRCs by recording-version markers. Copies of
   the same version still deduplicate. Two temporary maps keyed by whole track
   objects were removed; each row's identity is computed directly in the
   existing filtering pass.

10. **Hidden-lyrics frame race.** The full suite exposed one extra live-clock read
    after a retained lyrics panel became inactive. An already queued frame could
    execute before the previous effect job's cancellation completed. Frame and
    lifecycle callbacks now check current visibility before reading the clock.
    A panel initialized while hidden uses the supplied position until activated.
    Frame cadence, animation duration, drawing and geometry are unchanged.

11. **Provider completion race.** A fast provider could finish between the source
    selector's result check and its pending-request check. If no requests remained
    pending, the selector returned no match without inspecting the result that
    had just succeeded. This intermittently reported playable songs unavailable.
    The exhausted-pending path now checks every final result in source order
    before declaring failure. Four deterministic cases (primary and fallback
    completion on API 31 and 34) failed before the fix and pass afterward. Existing
    cancellation, source priorities and timeout budgets remain in force.

12. **Regression-fixture maintenance.** Existing assertions were brought into
    agreement with the current backup schema (6), Room schema (16), artwork
    dispatcher, full-title queries, neutral-DSP bypass, server-fed Search index
    and three-shelf initial Home window. Migration checks now include version 15
    and reject a genuinely future version (17). Robolectric fixtures grant the
    signature permission already present in the merged production manifest and
    reset process owners/admission state between application instances. Production
    UI and permission declarations were not changed to satisfy stale fixtures.
    The virtual-time resolver budget test now supplies its previously omitted
    metadata-search/detail collaborators, avoiding live service work while it
    tests the unchanged overall timeout. A Hero screenshot fixture waits for the
    failed native-image result to be delivered before advancing its transition
    and asserting the fallback's pixels; it previously captured the placeholder
    after observing only that fetching had started.
